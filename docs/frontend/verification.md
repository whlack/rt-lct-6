# Проверка production-клиента

Дата: 29 сентября 2026 года. Проверки выполнялись на отдельном Docker-стенде с PostgreSQL, Redis, Keycloak и MinIO. Рабочие данные и конфигурация окружения не использовались.

## Результаты

| Проверка                                         | Результат                        |
| ------------------------------------------------ | -------------------------------- |
| Обычные тесты frontend                           | 13 прошли                        |
| Обычные тесты backend                            | 38 прошли                        |
| Серверные интеграционные тесты                   | 10 прошли                        |
| Браузерные сценарии                              | 15 прошли, ошибок JavaScript нет |
| Типы, линтинг, форматирование workspace          | Прошли                           |
| Production Docker API, worker, tooling, frontend | Собраны                          |
| `API_UPSTREAM` в Vite и production nginx         | Другой адрес API проверен        |

Полный сценарий проверки — `scripts/frontend-check.sh --local`. При разработке браузерная часть повторялась на одноразовых стендах с уже проверенными production-образами после исправлений клиента. Финальный браузерный прогон выполнялся с `NODE_ENV=production` и текущей клиентской сборкой. Стенды удалены; снимки сохранены в [руководстве](./guide.md). Формальная приёмка и нагрузочные критерии ROADMAP этим прогоном не закрываются.

## Проверенные сценарии

1. Настоящий корпоративный вход OIDC/PKCE, профиль и права, три серверных KPI, фирменные ресурсы; отсутствие токенов в постоянном хранилище браузера.
2. Навигация без перезагрузки документа, переключение светлой/тёмной темы.
3. Создание контакта вуза, выбор основного контакта, связанные проекты.
4. Создание направления каталога и проекта через сервер.
5. Договор, лицензия, очистка необязательного вендора, назначение руководителя.
6. Настройка будущих этапов, защита первого этапа, фиксация workflow после перехода, блокировка без обязательного файла.
7. Прикрепление документа, отметка завершения, защищённое скачивание и совпадение содержимого.
8. Комментарий, ответ, редактирование, удаление текста с сохранением ответа.
9. Переходы, закрытие проекта, подтверждённая история.
10. Выгрузки XLS/XLSX/PDF/JSON с настоящим worker и скачиванием нужного задания.
11. Серверная статистика и PNG выгрузка.
12. Получение канонического XLSX-шаблона, загрузка, предпросмотр импорта, отдельное подтверждение, файл ошибок и появление вуза в реестре.
13. Состояния интеграций, поиск договора с клавиатуры, глубокие маршруты; десять экранов на ширине 390 px без переполнения страницы, пять мобильных разделов главной и меню.
14. Разрешённый список проектов КАМ, скрытая карточка возвращает 404, административный маршрут закрыт; изменение уровня отчётов запрещает API руководителю (403), независимая статистика остаётся доступной.
15. Выход удаляет защищённый интерфейс и завершает сессию.

Серверная проверка новых клиентских контрактов дополнительно проверяет сочетание фильтров, пагинацию/total, **текущий** ожидаемый этап, закрытые проекты, публичное имя ответственного и область видимости событий.

Прокси Vite и production nginx отдельно проверены с `API_UPSTREAM=http://env-api:4321`: адрес отличается от стандартного, путь `/api/health` сохраняется, ответ API 404 не подменяется страницей SPA, глубокий маршрут клиента открывается. Адрес задаётся при запуске контейнера без повторной сборки. Запрос с телом 25 МиБ + 1 КиБ проходит через nginx: его лимит 26 МиБ учитывает служебную часть multipart, лимит файла на API остаётся 25 МиБ. Полный повторный прогон `scripts/frontend-check.sh` прошёл через production frontend с его собственным прокси без вспомогательного gateway: 15 сценариев, ошибок JavaScript нет. После этого отдельно проверено увеличение лимита тела запроса.

## Внешние зависимости

LMS и сайт остаются `NOT_IMPLEMENTED` до получения и реализации контрактов источников. Генерация договоров требует утверждённых шаблонов и правил заполнения; сейчас доступны реальные прикрепления и отчёт проекта. Учётные записи/роли управляются в Keycloak. Расширенные дизайнерские профили импорта и география вузов не включались в текущую модель; сопоставление приведено в [анализе дизайна](./design-review.md).
