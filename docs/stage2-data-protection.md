# Подготовка защиты данных — серверный этап 2

Это технический реестр и перечень вопросов для заказчика. Применимость 152-ФЗ, статус системы и требования приказа ФСТЭК №117 подтверждает оператор/заказчик. Формальная оценка соответствия и аттестация этим этапом не выполняются.

Основание: [официально опубликованный приказ ФСТЭК от 11.04.2025 №117](https://publication.pravo.gov.ru/document/0001202506170011). При согласовании необходимо проверить действующую редакцию и применимость к конкретному оператору; исходная публикация сама по себе не определяет классификацию частной CRM.

## Реестр персональных данных

| Данные                                        | Цель / место                                                 | Кто получает доступ                                                          | Хранение                                                                                                      |
| --------------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Keycloak subject, ФИО, email, локальное ФИО   | Учёт сотрудника, назначения и авторство; Keycloak/PostgreSQL | Авторизованные сотрудники в доступных проектах, руководители, администраторы | Пока нужны учёт и аудит; конкретный срок утверждает оператор                                                  |
| ФИО, email, телефон контактов вуза            | Взаимодействие по проекту; PostgreSQL                        | По области видимости вуза/проекта и праву                                    | Срок проекта и обязательного хранения — согласовать                                                           |
| Авторство, даты, комментарии                  | Рабочая коммуникация и хронология; PostgreSQL                | По области видимости проекта                                                 | Текст удалённого комментария в API/отчётах скрыт; физическая политика удаления в БД требует решения оператора |
| Документы и метаданные                        | Подтверждение этапов; закрытый S3/PostgreSQL                 | Защищённый API с проверкой проекта                                           | Срок проекта/архива — согласовать; содержимое документов в отчёт не встраивается                              |
| Книга импорта, нормализованные строки, ошибки | Проверка и актуализация каталогов; S3/PostgreSQL             | Только автор с действующим catalogs.import                                   | 24 часа, затем очистка исходников и строк                                                                     |
| Выгрузка, параметры, связи проектов           | Отчётность; закрытый S3/PostgreSQL                           | Только автор с текущим правом и видимостью каждого проекта                   | 24 часа после формирования; затем минимальная запись аудита                                                   |
| Request/job ID, коды, время, агрегаты         | Диагностика; журналы/метрики                                 | Технический администратор                                                    | Ротация, срок и внешнее хранилище утверждаются оператором                                                     |
| Резервные копии PostgreSQL/S3/Keycloak        | Восстановление                                               | Выделенные администраторы                                                    | Частота, срок, шифрование и удаление копий — решение оператора                                                |

Токены не сохраняются в заданиях, персональные значения импортных строк не пишутся в журнал. Результаты отчётов могут содержать персональные данные — их нельзя публиковать как общедоступные ссылки. Миграции не объединяют записи вузов автоматически.

## Технические меры и организационные вопросы

| Область                        | Реализовано / предусмотрено                                                  | Что требуется от заказчика                                                                                                                           |
| ------------------------------ | ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Идентификация и аутентификация | OIDC JWT через Keycloak; повторные роли worker/скачивание                    | Политика аккаунтов, MFA, выдача/отзыв доступа, ответственные                                                                                         |
| Управление доступом            | Серверные права 10/20/30, область видимости, владелец задания                | Матрица полномочий, периодический пересмотр и разделение администрирования                                                                           |
| Ограничение потоков данных     | Закрытый S3, PostgreSQL/Redis в сети data, внешние запросы рендера запрещены | Сегментация серверной сети, firewall, перечень разрешённых интеграций                                                                                |
| Регистрация событий            | ID запросов/заданий, безопасные коды, SQL/API/queue метрики                  | Защищённое внешнее хранение, контроль целостности, мониторинг и регламент реагирования                                                               |
| Доступность и восстановление   | Идемпотентные задания, lease, backup/изолированное восстановление            | RPO/RTO, резервная площадка, график учений, доказательства восстановления                                                                            |
| Управление конфигурацией       | Prisma миграции, фиксированный lockfile, образы, проверки до выпуска         | Реестр версий, процесс одобрения изменений, контроль серверных секретов                                                                              |
| Защита транспорта              | Контракт TLS внешнего nginx, S3 TLS поддерживается конфигурацией             | Сертификаты, параметры TLS, доверенные прокси, управление ключами                                                                                    |
| Минимизация и хранение         | 24ч файлов заданий, очистка параметров/строк, исключение S3 ключей из API    | Цели/основания обработки, сроки постоянных данных/backup, процедуры удаления                                                                         |
| Уязвимости и вредоносный код   | Валидация книг/формул/размера архива, изоляция рендера                       | Обновление ОС/образов, сканирование зависимостей и файлов, антивирус по модели угроз                                                                 |
| Требования 152-ФЗ / №117       | Архитектурная модель и технический реестр для дальнейшего анализа            | Категории/количество субъектов, класс/уровень системы, модель угроз, набор мер, документы оператора, оценка и применимость сертифицированных средств |

Наличие перечисленных механизмов не означает полного выполнения всех требований закона или приказа. LMS/сайт, клиентские экраны и организационные процессы остаются отдельными этапами.
