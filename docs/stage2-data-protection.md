# Подготовка защиты данных — серверный этап 2

Это технический реестр и перечень вопросов для заказчика. Применимость 152-ФЗ, статус системы и требования приказа ФСТЭК №117 подтверждает оператор/заказчик. Формальная оценка соответствия и аттестация этим этапом не выполняются.

Основание: [официально опубликованный приказ ФСТЭК от 11.04.2025 №117](https://publication.pravo.gov.ru/document/0001202506170011). При согласовании необходимо проверить действующую редакцию и применимость к конкретному оператору; исходная публикация сама по себе не определяет классификацию частной CRM.

## Дополнение: каркас этапа 3

IntegrationSyncRun хранит локальный UUID инициатора ручного задания, источник, статус, времена, число попыток и безопасный код ошибки. Профили Keycloak, токены и внешние данные не сохраняются. Поле инициатора связано с User и обнуляется при его удалении. Просмотр глобальной служебной истории требует integrations.manage (начальный уровень 20); ручной запуск — integrations.sync (20), перед выполнением право проверяется повторно.

Завершённая история автоматически удаляется через 90 дней (SYNC_RUN_RETENTION_DAYS). Активные задания не удаляются. Срок является технической настройкой, организационную допустимость подтверждает оператор. Резервные копии подчиняются уже описанной политике резервирования; удаление из рабочей БД не сокращает срок существующих копий. LMS/WEBSITE не реализованы, новые категории персональных данных из источников сейчас не обрабатываются. До подключения реальных адаптеров потребуется согласовать состав данных, основание обработки, доступ технического исполнителя и сроки хранения.

## Дополнение после ревью безопасности

Политика видимости содержит UUID КАМ, режим и разрешённые UUID вузов/проектов; управляющий доступ только у администратора. Для руководителей и администраторов ограничений нет. Политика и оба списка читаются одним SQL-снимком; результат фонового отчёта повторно проверяется при скачивании. Удаление комментария очищает текст, конкурентное редактирование не восстанавливает его.

Сервис Keycloak ограничен чтением сотрудников. Административный пароль передаётся Keycloak для bootstrap и отдельному setup-контейнеру; API и worker его не получают. Runtime работает без root, без исходников приложения и прямых административных credentials; лимиты защищают загрузки и очереди от неограниченного потребления памяти и хранения.

В pnpm lockfile mysql2 обновлён до 3.24.4 в пределах основной версии. Vitest обновлён до 4.1.11 с исправлением [GHSA-82fw-gwwq-j7x9](https://github.com/advisories/GHSA-82fw-gwwq-j7x9); обычные тесты клиента проходят на новой версии. Остаточное предупреждение: [GHSA-ggr8-5vv4-36mx](https://github.com/advisories/GHSA-ggr8-5vv4-36mx), deepmerge-ts 7.1.5 через Prisma/@prisma/config. Исправление опубликовано в 8.0.0, текущая стабильная Prisma 7.10.0 использует 7.1.5; принудительная подмена основной версии не выполнена. Уязвимость требует циклических объектов JavaScript, которые JSON-запрос CRM создать не может; прямого вызова deepmerge из HTTP/импорта в прикладном коде нет. Prisma/@prisma/config также присутствуют в runtime-образах как транзитивные optional peer-зависимости @prisma/client, без вызовов из HTTP-сценариев. Предупреждение требует отслеживания совместимого обновления; это не подтверждение отсутствия всех уязвимостей.
