# Проверка серверного этапа 2

## Прогон после исправлений ревью — 29 сентября 2026

Прогон `rt-crm-acceptance-20260929110944-1718` завершился успешно: `scripts/acceptance.sh --local`, изолированные Linux-контейнеры Docker Desktop arm64. Рабочие данные, `.env` и Compose не изменялись. Приложение совместно использовало CPU 0–3, генератор — 4–5; лимиты памяти приложения суммарно меньше 8 ГБ, worker — 2 CPU / 2 ГБ. На сервере заказчика измерения необходимо повторить.

### Проверенные исправления

- 32 обычных теста backend, 2 frontend и 8 PostgreSQL/Redis интеграционных тестов прошли; типы, линтинг и сборки приложений прошли. Клиентские тесты также прошли после обновления Vitest до 4.1.11; UI не менялся.
- Финальные production Docker-образы API, worker и frontend пересобраны с обновлённым frozen lockfile; все три сборки прошли.
- Валидация DTO и OpenAPI проверены через HTTP без автоматически выпущенных метаданных; UUID, страницы и неизвестные поля проверяются сервером.
- Политики видимости КАМ проверены для всех данных, отдельных проектов/вузов и пустого списка; руководитель и администратор не ограничиваются. Проверены списки, главная, статистика, отчёты и повторная проверка скачивания.
- Проверены nullable-поля, одинаковая дата лицензии без повторного события, конкурентное редактирование/удаление комментария и запрет восстановления удалённого текста.
- Старый execution ID и истёкшая аренда не записывают ошибки строк; применение строки и processedAt атомарны. Проверены повторное выполнение и ограничения числа заданий/загрузок.
- Сервис Keycloak читает 25 КАМ, попытка создать пользователя возвращает 403. HTTP-заголовок скачивания с кириллицей проверен реальным Node-сервером.
- JSON-экспорт, выбор и порядок колонок проверены; минимальная страница проектов не содержит вложенных файлов и всех этапов.
- Все четыре фоновых сбоя восстановлены: Redis — 1 попытка, S3/Keycloak/SIGKILL worker — по 2 попытки; результаты скачаны.
- Backup и изолированный restore с `--local` и `--prod` прошли: CRM содержит 10 000 проектов, восстановлены Keycloak и 20 объектов S3 с проверкой checksum. После перезапусков API/worker готовы.

### Нагрузка с операциями записи

Набор: 1 000 вузов, 10 000 проектов и 200 000 исходных событий. 50 пользователей выполняют чтение, переходы этапов, создание/изменение/удаление комментариев. Список отчётов читают роли с соответствующим правом. Одновременно отправлены 10 отчётов, включая XLSX на 10 000 проектов; все успешно сформированы и скачаны. На фоне интерактивной нагрузки проверено и применено 20 000 строк импорта, повторное применение не создаёт дубли.

Согласованный пользователем критерий — **p95 каждой интерактивной операции ≤1 000 мс и отсутствие ошибок**. Прогон соответствует: 5 625 интерактивных запросов, ошибок 0. Общий p95 — 427.8 мс приведён только справочно; решение принимается по каждой операции. Polling заданий и ожидание результатов учитываются отдельно.

| Список проектов            |      750 |   395.7 |        813.9 |

Единичные максимумы превышают 1 секунду; утверждение об абсолютном пределе для каждого запроса не делается. Проверка книги — 11.52 с, применение — 77.11 с. Максимальная наблюдаемая память worker — 601.6 MiB, API — 350.2 MiB, PostgreSQL — 205.1 MiB; это дискретные замеры раз в пять секунд.

Порог не ослаблялся после неуспешного прогона: устранена повторная загрузка полной карточки перед переходом этапа, проверка доступа/состояния осталась внутри транзакции с блокировкой. Артефакты находятся в игнорируемой `.artifacts/rt-crm-acceptance-20260929110944-1718/`: load.json, faults.json, resources.jsonl, OpenAPI, отчёты, статистика и резервные копии.

Остаточное предупреждение зависимости Prisma и организационные вопросы приведены в [реестре защиты данных](./stage2-data-protection.md). Реальные LMS/WEBSITE остаются NOT_IMPLEMENTED; каркас не означает завершённую интеграцию.
