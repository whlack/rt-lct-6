# Проверка серверного этапа 2

Дата: 28 сентября 2026. Результаты относятся к изолированным Linux-контейнерам Docker Desktop (arm64), а не к рабочей БД. Все сервисы приложения совместно ограничены CPU 0–3; отдельный контейнер генератора использует CPU 4–5. Лимиты памяти сервисов приложения суммарно меньше 8 ГБ, worker — 2 CPU / 2 ГБ. Измерения нужно повторить на согласованном сервере заказчика перед окончательной эксплуатационной приёмкой.

- Запросов: 3168; серверных ошибок: 0.

## Доказательства и воспроизведение

Запуски scripts/acceptance.sh --local и --prod сохраняют в игнорируемом .artifacts/ нагрузку load.json, EXPLAIN explain.json, ресурсы resources.jsonl, состояния faults.json, OpenAPI openapi.json, файлы отчётов/графиков, dump PostgreSQL/Keycloak и закрытые объекты с manifest S3. Токены не сохраняются. Реальные секреты и рабочие Compose в Git отсутствуют.

Основной локальный прогон: rt-crm-acceptance-20260928231226-49165. Production-контракт: rt-crm-acceptance-20260928231814-50269. Production-копия формировалась во временном каталоге вне репозитория; использованы готовые образы из отдельного локального тестового registry. Во время проверки рабочие сети, тома и БД не использовались.

## Незавершённая общая приёмка и поставка

- Мобильная версия, навигация без перезагрузки, экраны и руководства со скриншотами относятся к отдельному клиентскому этапу.
- Классификацию, применимость нормативных требований, организационные меры, RPO/RTO и сроки постоянного хранения подтверждает заказчик.
- Для пяти последовательных MR требуется development с серверным этапом 1. MR !1 ещё ожидает слияния team lead; самостоятельно сливать его и продвигать изменения в main/development запрещено. После каждого слияния следующий MR проверяется относительно новой базы.
