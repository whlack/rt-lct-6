# Серверный этап 2

Клиент использует эти контракты; рабочие сценарии описаны в [руководстве](./frontend/guide.md). Новые права: dashboard.read — 10; reports.read, reports.export, statistics.read — 20. Импорт использует catalogs.import — 20. Право не заменяет проверку видимости данных.

## Показатели

GET /api/dashboard возвращает universities, activeProjects, actionRequiredProjects, calculatedAt. Вузы — все доступные. Активный проект не закрыт; требует действий, если текущий этап ожидает KAM. Счётчик не ограничивается проектами, за которые лично отвечает вызывающий КАМ.

## Отчёты

GET /api/reports/projects принимает dateFrom/dateTo (YYYY-MM-DD, только вместе), universityId, directionId, programId либо productId, responsibleSubject и status (ACTIVE/CLOSED). Период выбирает проекты с событиями истории; поля отражают текущее состояние. Границы дней вычисляются в REPORT_TIMEZONE (Europe/Moscow). page — от 1, pageSize — 1–100, по умолчанию 25.

GET /api/reports/projects/:id возвращает полный отчёт без периода: этапы, требования документов, метаданные файлов, комментарии и события. Текст удалённых комментариев и ключи S3 не выдаются.

Пустая выборка — 200 с пустыми rows и total=0; недоступный конкретный проект — 404; неправильные фильтры — 400; отсутствие токена — 401; отсутствие права — 403.

## Асинхронные файлы

POST /api/reports/exports принимает format=xls|xlsx|pdf|json и фильтры сводки либо projectId без фильтров. Ответ 202: `{ "id": "UUID", "status": "QUEUED" }`. XLS записывается как BIFF8, длинная хронология разделяется на листы по 65 000 строк. Значения текста, начинающиеся с =, остаются текстом. PDF содержит повторяемые заголовки, кириллицу и номера страниц. Файл формируется по одному снимку данных; дальнейшие изменения не меняют уже сформированный результат.

GET /api/jobs/:id возвращает статус, progress, errorCode, createdAt/startedAt/completedAt/expiresAt. Опрос раз в 1–3 секунды достаточен для клиента. После SUCCEEDED скачать GET /api/jobs/:id/file с тем же Bearer token. Доступ только автору; текущие роли запрашиваются заново в Keycloak, право и все включённые проекты проверяются перед выдачей. Неготовый файл — 409, просроченный — 410, потеря доступа — 403. Публичных S3-ссылок нет. Результат доступен 24 часа.

Пример запроса через Swagger: авторизоваться Bearer token, выполнить POST /api/reports/exports с `{ "format": "xlsx", "dateFrom": "2026-03-01", "dateTo": "2026-03-31" }`, сохранить id, дождаться SUCCEEDED через GET /api/jobs/:id, скачать file. Общий отчёт проекта: `{ "format": "pdf", "projectId": "UUID" }`.

## Статистика

GET /api/statistics принимает те же фильтры. Возвращает status.active/closed, directions (id/name/count), months (month/created/closed), timezone, filters и generatedAt. Первые два графика используют отчётную выборку по истории. Месячный — даты создания и закрытия; месяцы без событий заполнены нулями. Без периода — последние 12 месяцев, максимум 36. Длинные графики разделяются на части при формировании PDF, сохраняя общий масштаб.

POST /api/statistics/exports: те же фильтры и format=png|pdf. Ответ 202 и скачивание через jobs. JSON, SVG и оба файла строятся из одного серверного агрегата. Пример: `{ "format": "png", "dateFrom": "2026-01-01", "dateTo": "2026-09-30" }`.

## Импорт

Используется только базовый шаблон из docs/catalog-import.md: Вузы, Направления, Программы и продукты, Сотрудники. Книга может содержать часть листов. POST /api/catalog-imports — multipart/form-data с file (.xls/.xlsx, до 10 МБ). Ответ 202 означает начало проверки, не запись данных.

| Лист                 | Заголовки первой строки                     |
| -------------------- | ------------------------------------------- |
| Вузы                 | Название вуза                               |
| Направления          | Название направления                        |
| Программы и продукты | Тип, Название (Тип: Программа либо Продукт) |
| Сотрудники           | Email, ФИО                                  |

GET /api/catalog-imports/:id?page=1&pageSize=25 возвращает фазу VALIDATE/APPLY, состояние, счётчики и строки: sheet, rowNumber, key, data, action, result, errors, processedAt. Предварительные action: CREATE/UPDATE/SKIP/ERROR; итоговые result: CREATED/UPDATED/SKIPPED/ERROR. При PREVIEW можно скачать XLSX ошибок через /api/jobs/:id/file.

POST /api/catalog-imports/:id/apply — отдельное подтверждение после изучения preview. Возвращает 202; повторное применение завершённого задания возвращает его текущий статус и не записывает строки второй раз. Совпадения в БД и область видимости проверяются снова. Ошибка одной строки не отменяет другие валидные строки. После SUCCEEDED доступны итоговые счётчики и новый XLSX ошибок. Исходник и строки доступны 24 часа с загрузки, затем очищаются.

Новые вузы назначаются автору импорта. Существующие должны быть видимы. Лист Сотрудники ищет ровно одну включённую учётную запись Keycloak по email, не меняет её и сохраняет ФИО только в CRM. Новый вход обновляет исходный профиль, но сохраняет локальное ФИО.

Полная схема, примеры и ошибки находятся в /api/docs; машинный OpenAPI — /api/docs-json. [Эксплуатация и очереди](./stage2-operations.md), [реестр данных и меры](./stage2-data-protection.md), [архитектурная модель](./architecture/crm-stage2.archimate).

## Видимость КАМ

Только администратор с `visibility.manage` читает и заменяет политику: `GET/PUT /api/visibility/:subject`, где subject — UUID сотрудника Keycloak. Политика применима к включённому КАМ; для руководителей и администраторов ограничения не действуют.

- `ASSIGNED` — прежний доступ по назначениям вузов и ответственности за проект. Значение по умолчанию для существующих сотрудников.
- `ALL` — все вузы и проекты; списки должны быть пустыми.
- `SELECTED` — только `universityIds` и `projectIds` (каждый список до 1000 уникальных UUID). Разрешённый вуз открывает все его проекты. Отдельный проект не открывает другие проекты и карточку его вуза. Пустые списки закрывают предметные данные. Назначения и создание нового вуза не расширяют эту политику; новый вуз отдельно добавляет администратор.

Пример: `{ "mode": "SELECTED", "universityIds": ["UUID"], "projectIds": [] }`. Область применяется к карточкам, спискам, показателям, статистике, импорту и отчётам. Политика читается из PostgreSQL для нового API-запроса и повторно при выполнении задания и скачивании результата; права на операции по-прежнему проверяются отдельно.

## Список проектов и очищаемые поля

`GET /api/projects?page=1&pageSize=25` возвращает `{rows,total,page,pageSize}`; pageSize — 1–100. Строка содержит идентификаторы и публичные профили ответственных, вуз/направление/программу или продукт, currentStage (включая expectedActor и expectedContact), stageCount, createdAt/closedAt. Полный workflow и метаданные файлов находятся в отдельной карточке проекта. Это изменение прежнего ответа-массива следует учесть при разработке клиента.

Фильтры реестра: universityId, directionId, programId, productId, responsibleSubject (UUID), status=ACTIVE|CLOSED, search (до 200 символов; вуз, направление, программа/продукт, номер договора). `actionRequired=true` выбирает только незакрытые проекты, чей **текущий** этап ожидает действия КАМ; ожидание вуза и будущие этапы не учитываются. Все фильтры сочетаются с областью видимости и пагинацией.

`GET /api/projects/activity` с правом `projects.read` возвращает до 25 последних событий видимых проектов: ID/тип/время события, публичный профиль автора и краткое описание проекта. Публичные профили учитывают локальное отображаемое имя и не раскрывают служебный displayNameOverride.

`GET /api/config` доступен без авторизации и возвращает только `{keycloak:{url,realm,clientId}}` для публичного OIDC-клиента. Пароли, конфигурация сервисного клиента и другие переменные окружения в ответ не входят. Клиент обращается к `/api/me` после корпоративного входа.

В PATCH проекта `vendor`, `contractNumber`, `licenseSignedAt`, `licenseExpiresYear` можно очистить явным null. В PATCH контакта null очищает email/phone; отсутствующее поле сохраняет прежнее значение. Хотя бы один канал должен остаться. Удалённый комментарий имеет body=null; повторное редактирование возвращает 409.

## Колонки и JSON

В POST отчёта optional `columns` задаёт порядок колонок сводки: id, university, direction, offeringType, offering, status, stage, responsible, supervisor, createdAt, closedAt, vendor, contractNumber, licenseSignedAt, licenseExpiresYear, transferStatus. Без поля выбираются все; пустой, повторяющийся или неизвестный список отклоняется. Для отчёта проекта настройка относится только к секции сводки.

Пример: `{ "format": "json", "columns": ["university", "id"] }`. JSON-файл имеет title/generatedAt/timezone и sections; каждая секция содержит title, columns и rows с упорядоченными значениями. Полный JSON проекта содержит также этапы, документы, комментарии и историю; ключи S3 и удалённые тексты не включаются. Создание и получение проходят тот же `/api/jobs` и повторные проверки доступа.

Полная спецификация всех этапов доступна через Swagger вне production. См. [руководство OpenAPI](./openapi.md) для входа, ошибок, загрузки файлов и последовательностей фоновых операций.
