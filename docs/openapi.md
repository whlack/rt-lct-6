# Документация API CRM

## Доступ и окружения

Swagger UI: `/api/docs`; OpenAPI JSON: `/api/docs-json`; YAML: `/api/docs-yaml`. При `NODE_ENV=production` ни один из этих адресов и ресурсы Swagger не регистрируются: ответ 404. В development, test и staging они открываются без входа. Production-образ сохраняет `NODE_ENV=production`; на других стендах значение переопределяется явно. Не переносите локальное `NODE_ENV=development` в серверный Compose.

Спецификация собирается средствами NestJS из контроллеров, DTO и схем ответов, содержит уникальные operationId, русские описания, ограничения, HTTP-ошибки и синтетические примеры. Примеры идентификаторов заменяйте существующими ID своего стенда. Базы данных и внешние источники для генерации примеров не читаются. Описания обновляются вместе с API; статической копии спецификации, которую надо редактировать вручную, нет.

## Вход и права

Получите access token realm `crm` через обычный вход Keycloak. Нажмите **Authorize**, вставьте сам токен без `Bearer` и выполните операцию. Swagger добавляет заголовок `Authorization: Bearer …`. Токен не сохраняется между перезагрузками. `/api/config`, `/api/health`, `/api/ready` не требуют токена.

`GET /api/me` возвращает локальный `id`, Keycloak `subject`, уровень роли, эффективные `permissions` и `visibility`. В назначениях передаётся **subject Keycloak**, а не локальный `id`. Достаточное право не отменяет проверку видимости. Уровни: 10 — КАМ, 20 — руководитель, 30 — администратор; дополнительные ограничения уровня перечислены у каждой операции. Минимальные уровни обычных прав изменяемы; управление правами и видимостью всегда требует администратора.

Режимы видимости КАМ: ASSIGNED — назначения и ответственность, ALL — все объекты, SELECTED — явные списки. Выбранный вуз открывает все его проекты. Отдельный проект не открывает вуз и соседние проекты. Пустой SELECTED закрывает предметные данные; создание и назначения не расширяют его автоматически.

## Ввод, ответы и ошибки

В операциях с DTO неизвестные поля body/query отклоняются. Маршруты без query DTO не валидируют неиспользуемые query-параметры. UUID, перечисления, строки, массивы, числа и даты проверяются сервером. Пагинация начинается с 1, обычно 25 записей, максимум 100. Каталоги, сотрудники, вузы, контакты, назначения, комментарии и история проекта сейчас возвращают массивы без пагинации; не передавайте им несуществующие параметры страницы. Значения времени сериализуются в ISO 8601, nullable-поля указаны в схемах.

Типичный ответ ошибки NestJS:

```json
{
  "statusCode": 400,
  "message": ["property unexpected should not exist"],
  "error": "Bad Request"
}
```

`message` бывает строкой либо массивом. Поле `error` может отсутствовать у `HttpException`, например при лимите. `/api/ready` имеет собственный ответ 503: `{ "status": "unavailable" }`. Технические сообщения и коды сохраняются на языке действующего API.

| Код | Значение                                                                                                       |
| --- | -------------------------------------------------------------------------------------------------------------- |
| 400 | Некорректные параметры, UUID, тело или предметное условие                                                      |
| 401 | Нет Bearer token, токен недействителен или нет роли CRM                                                        |
| 403 | Нет права, достаточного уровня либо видимости                                                                  |
| 404 | Объект или источник отсутствует; чужое задание скрывается                                                      |
| 409 | Конфликт состояния: этап изменился, проект закрыт, результат не готов, импорт не проверен, источник недоступен |
| 410 | Истёк срок хранения импорта или файла результата                                                               |
| 413 | Файл превышает размер, ограниченный загрузчиком                                                                |
| 429 | UPLOAD_LIMIT_REACHED, EXPORT_LIMIT_REACHED или IMPORT_LIMIT_REACHED                                            |
| 503 | Каталог Keycloak временно недоступен; для ready — недоступна БД                                                |
| 500 | Необработанная внутренняя ошибка, в том числе отказ БД/хранилища; диагностика по x-request-id                  |

Состав ошибок конкретной операции указан в Swagger. Ответ API содержит `x-request-id`; сохраните его для поиска ошибки в журналах. Не включайте токены и содержимое файлов в обращение администратору.

## Проекты, workflow и файлы

Реестр `/api/projects` принимает фильтры universityId, directionId, programId/productId, responsibleSubject, status и search. `actionRequired=true` оставляет открытые проекты, текущий этап которых ожидает KAM; назначение текущего пользователя не является дополнительным условием. Для выключения фильтра удалите параметр: значение `false` не поддерживается. В текущем реестре одновременные programId и productId применяются как AND и обычно дают пустую выборку; в отчётах это сочетание отклоняется с 400.

1. Получите доступные вузы, каталоги и КАМ через реестры.
2. Создайте проект: вуз, направление, ровно один `programId` или `productId`, `responsibleSubject`. Workflow создаётся автоматически.
3. Пока проект на «Формирование проекта», руководитель может заменить последующие этапы. В `stages` начальный этап не передаётся; он сохраняется сервером. Для UNIVERSITY нужен контакт этого вуза, для KAM `expectedContactId` запрещён.
4. Прикрепляйте файлы только к текущему этапу и одному из его documentTypeId. В Swagger выберите файл в поле `file` запроса multipart/form-data. Непустой файл до **25 МиБ**; png/jpg/jpeg/pdf/zip/gz/rar/doc/docx/xls/xlsx.
5. Для перехода передайте `expectedStageId` из актуальной карточки. Наличие обязательных прикреплённых документов проверяется атомарно. Флаг COMPLETED не является дополнительным условием наличия файла. После первого перехода workflow заблокирован.
6. Руководитель закрывает проект на последнем этапе при выполнении требований к документам. Редактирование/удаление комментария доступно его автору либо пользователю с уровнем не ниже 20. Комментарии сохраняют ответы через parentId; при мягком удалении текст очищается.

Скачивание `/api/projects/{id}/files/{fileId}` возвращает application/octet-stream, Content-Disposition и Content-Length. Swagger предлагает скачать бинарный ответ. Ключи S3 и публичные ссылки не выдаются.

## Отчёты и фоновые результаты

Период задаётся парой dateFrom/dateTo. Границы включительны в REPORT_TIMEZONE, по умолчанию Europe/Moscow. На сервере используется полуоткрытый диапазон до начала следующего дня после dateTo. Период отбирает проекты по наличию события истории, но показывает текущие значения полей. Несколько событий не дублируют строку проекта. programId и productId нельзя совмещать.

Создайте сводку через `POST /api/reports/exports`:

```json
{
  "format": "xlsx",
  "dateFrom": "2026-01-01",
  "dateTo": "2026-03-31",
  "columns": ["university", "direction", "offering", "status", "responsible"]
}
```

Для полного отчёта используйте `{ "format": "pdf", "projectId": "aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa" }` без фильтров. Форматы: настоящий BIFF8 XLS, XLSX, PDF и JSON. columns определяет порядок колонок; без него выбираются все. Полный отчёт содержит текущие поля, требования этапов, метаданные документов, комментарии и всю историю; вложенные файлы не встраиваются.

После ответа **202** сохраните id, опрашивайте `GET /api/jobs/{id}` и при SUCCEEDED скачайте `GET /api/jobs/{id}/file`. 202 означает принятие, а не завершение. Файл по умолчанию хранится 24 часа. Скачивание доступно только автору после повторной проверки актуальных прав и всех включённых проектов. При потере видимости требуется новая выгрузка. 409 — файл ещё не готов, 410 — срок истёк, FAILED содержит безопасный errorCode.

`GET /api/statistics` возвращает распределение активных/закрытых проектов, направления и месяцы создания/закрытия. Первые два графика используют выборку отчётов; третий — даты жизненного цикла. Без периода — 12 месяцев, максимум — 36, нулевые месяцы присутствуют. Для PNG/PDF отправьте те же фильтры и `format` в `POST /api/statistics/exports`; дальнейшая последовательность та же.

## Импорт каталогов

1. В `POST /api/catalog-imports` выберите XLS/XLSX в `file`. Исходный файл сохраняется в закрытом хранилище, ответ 202 возвращает id.
2. Опрашивайте `GET /api/catalog-imports/{id}?page=1&pageSize=25`. В PREVIEW просмотрите counts и строки CREATE/UPDATE/SKIP/ERROR. При наличии сформированного файла ошибок скачайте `/api/jobs/{id}/file`.
3. Отправьте `POST /api/catalog-imports/{id}/apply`. Ответ 202 означает принятие; состояние и результаты строк доступны через тот же GET.
4. Повторное apply уже запущенной фазы APPLY не применяет строки второй раз. Ошибочные строки не записываются и не отменяют валидные.

Поддерживается часть согласованных листов: Вузы (название), Направления (название), Программы и продукты (тип и название), Сотрудники (email и ФИО). Структура не расширяется. Лимиты по умолчанию: 10 МиБ исходного файла, 20 000 строк, 50 МиБ распакованного XLSX. Пустые строки игнорируются. Формулы в значимых ячейках, неизвестные непустые листы, неверные заголовки, шифрование и конфликтующие ключи получают ошибки проверки.

Импорт сотрудников только сопоставляет существующие записи Keycloak; учётные записи не создаются и не меняются. ФИО сохраняется как локальное переопределение и не теряется после входа. Новые вузы получают автора как создателя и назначенного сотрудника; существующие проверяются по области видимости. Подробности: [спецификация импорта](./catalog-import.md).

## Интеграции

LMS и WEBSITE имеют NOT_IMPLEMENTED, reason=SOURCE_NOT_IMPLEMENTED и nextRunAt=null. POST sync возвращает 409 и не создаёт задания. Это готовый каркас инфраструктуры, реальное получение и изменение данных не реализованы. История требует integrations.manage, запуск integrations.sync. `/api/jobs` не обслуживает задания интеграций.
