# Эксплуатация серверного этапа 2

## Linux и образы

Начальный стенд: Linux, 4 vCPU, 8 ГБ RAM; генератор нагрузки — отдельно. Установить Docker Engine и Compose plugin по [официальной инструкции Docker](https://docs.docker.com/engine/install/). Для первого запуска скопировать `docker-compose.yaml.example` в игнорируемый `docker-compose.yaml`, `.env.example` в `.env`, задать пароли и внешний URL Keycloak. В репозитории нет рабочего production Compose.

```sh
scripts/migrate.sh --local
scripts/start.sh --local
scripts/status.sh --local
scripts/logs.sh --local
scripts/stop.sh --local
```

Миграция выполняется отдельным профилем, запуск сервисов её не выполняет. Stop сохраняет тома. Источники локально подключаются только к API/worker; серверные образы запускаются без bind mount исходников.

Для сервера собрать и опубликовать три образа из backend/Dockerfile: target `production` для API и target `worker-production` для worker и target `tooling` для миграций и настройки. Зафиксировать теги или digest в серверном `docker-compose.prod.yaml`; для migrate, keycloak-config и minio-setup использовать образ tooling той же версии. API и worker работают как node, с production-зависимостями и без tsx/линтера; setup остаётся отдельным одноразовым контейнером. Prisma/TypeScript сохраняются в транзитивном peer-дереве @prisma/client, без прямых команд приложения. У backend — команда `node dist/main.js`, у worker — `node dist/worker.js` (либо оставить CMD production-образа; прямой запуск Node обеспечивает передачу SIGTERM), у migrate — `prisma migrate deploy`, затем `prisma db seed`. Убрать build и исходные bind mounts. Имена сервисов backend/worker/postgres/redis/keycloak сохраняются для scripts.

Worker включает Chromium headless shell, системные библиотеки и DejaVu Sans с кириллицей. Браузер устанавливается при сборке, по [инструкции Playwright](https://playwright.dev/docs/browsers). Сеть при рендеринге запрещена; шрифт встроен в HTML. Начальные ограничения worker: 2 CPU, 2 ГБ RAM, две выгрузки и один импорт, graceful shutdown до 120 секунд. При превышении срока Docker завершает процесс; lease и построчные транзакции позволяют повтор.

В production Keycloak запускается в режиме start с настроенным hostname/proxy и TLS внешнего прокси. start-dev из примера предназначен для локального/тестового окружения. Внешний nginx завершает TLS и направляет /api/ в API, Keycloak — в его отдельный upstream. Frontend nginx обслуживает собранные файлы Vite и сам проксирует /api/ в API_UPSTREAM из .env, передаваемый через environment контейнера. Внешний прокси также может направлять все запросы CRM во frontend. Прокси должен пропускать файлы проектов до 25 МиБ плюс multipart overhead; импорт ограничен IMPORT_MAX_BYTES (по умолчанию 10 МиБ) на API; доверенные forwarded headers настраивать только для своего прокси. Worker health/metrics порт не публиковать наружу. S3 бакет закрытый и выделенный для CRM; Redis/PostgreSQL доступны только во внутренней сети. Для внешнего S3 убрать локальные minio/minio-setup и их зависимости из серверной конфигурации.

## Переменные

| Переменная                              | Назначение / исходное значение                          |
| --------------------------------------- | ------------------------------------------------------- |
| REDIS_URL                               | Адрес, база, при необходимости credentials/TLS очередей |
| REPORT_TIMEZONE                         | Границы дат и месяц графика, Europe/Moscow              |
| JOB_RETENTION_HOURS                     | Файлы, исходные книги и построчные результаты, 24 часа  |
| EXPORT_CONCURRENCY / IMPORT_CONCURRENCY | Параллельность worker, 2 / 1                            |
| REPORT_MAX_PROJECTS                     | Предельный размер сводной выгрузки, 50 000              |
| IMPORT_MAX_BYTES                        | Сжатый/исходный файл, 10 485 760                        |
| IMPORT_MAX_ROWS                         | Непустые строки всех листов, 20 000                     |
| IMPORT_MAX_UNCOMPRESSED_BYTES           | Реальный распакованный XLSX, 52 428 800                 |
| REPORT_FONT_PATH                        | Необязательный путь встроенного шрифта в worker         |
| WORKER_HEALTH_PORT                      | Внутренний health/metrics, 3001                         |
| BACKUP_DIR                              | Каталог резервной копии для backup/restore-check        |

KEYCLOAK_PUBLIC_URL задаёт issuer JWT, KEYCLOAK_INTERNAL_URL — адрес адаптера в сети Docker; FRONTEND_ORIGIN конфигурирует клиент через env. Остальные параметры PostgreSQL/Keycloak/S3 описаны в .env.example. Токены в БД заданий не записываются.

## Очереди и восстановление

PostgreSQL содержит подтверждённое состояние и outbox. Redis содержит две очереди crm-exports и crm-imports, постоянный jobId включает UUID и фазу импорта. Диспетчер раз в пять секунд доставляет пропущенные записи. Lease — 15 секунд с heartbeat каждые пять секунд. Временная ошибка даёт до трёх попыток с экспоненциальной задержкой; ошибка доступа/данных — окончательная.

Состояния: QUEUED → RUNNING → SUCCEEDED либо FAILED. Импорт проходит PREVIEW, отдельный apply возвращает его в QUEUED/APPLY. Результат после срока становится EXPIRED. При потере доступа создать новую выгрузку. Не менять status/executionId/processedAt вручную и не очищать всю Redis DB. После временной недоступности восстановить зависимость и дождаться диспетчера; окончательно неуспешное задание создаётся заново пользователем.

Безопасные коды: INVALID_DATA, ACCESS_UNAVAILABLE, TEMPORARY_FAILURE, RETRY_EXHAUSTED. Построчные ошибки FORMULA/REQUIRED/EMAIL/TYPE/TOO_LONG/AMBIGUOUS/NOT_FOUND/SCOPE/ROW_REJECTED доступны только автору книги. Содержимое строк в журналах отсутствует.

API возвращает x-request-id; журнал содержит request/job ID, маршрут без параметров и код результата. GET /api/metrics доступен администратору; worker /metrics — только во внутренней сети. Метрики: crm_api_seconds, crm_sql_seconds, crm_queue_jobs, crm_job_seconds, crm_job_wait_seconds, crm_job_errors_total, crm_job_retries_total, crm_files_cleaned_total и память процесса. Алерты: растущая очередь, FAILED, недоступный worker, p95 API >1с, отсутствие очистки при наличии просроченных файлов.

## Обновление

Перед обновлением создать согласованную резервную копию. Задать новые теги API/worker/migrate, запустить `scripts/deploy.sh --prod`: pull → migrate/seed → start. При ошибке миграции новый start не выполняется. Предыдущая версия продолжает работать только если её схема осталась совместимой.

Коллизии normalizedName останавливают миграцию транзакционно и называют таблицу. Не объединять вузы и не перепривязывать проекты автоматически. После согласованной миграции данных повторить deploy. Для других ошибок исследовать миграционный журнал, восстановить стенд из backup, проверить исправление там; prisma migrate resolve применять только после подтверждения фактического состояния SQL. Откат образов не является откатом схемы.

## Резервирование и восстановление

`scripts/backup.sh --local|--prod` останавливает API/worker/Keycloak на время согласованного снимка CRM, Keycloak и выделенного S3-бакета, затем возвращает сервисы. Копия содержит персональные данные и закрытые ключи объектов: права каталога 0700, шифрование и внешнее хранение организует оператор. Не резервировать S3 независимо от ссылок PostgreSQL без общего окна записи либо согласованного snapshot/version manifest.

`BACKUP_DIR=/path/to/backup scripts/restore-check.sh --local|--prod` проверяет dump и S3 manifest в отдельных PostgreSQL/MinIO контейнерах, без сетевого доступа к рабочим сервисам. Перед реальным восстановлением остановить запись, восстановить CRM и Keycloak из одной копии, затем S3 по manifest, проверить количество проектов, контрольные суммы и авторизацию; новый Redis допустим, поскольку задания восстанавливаются из БД. Сначала обязательно выполнить восстановление на изолированном стенде. RPO/RTO, частоту, срок хранения, ключи шифрования и ответственных утверждает оператор.

## Приёмка

`scripts/acceptance.sh --local` собирает готовые API/worker образы и создаёт временный Compose вне репозитория. `--prod` берёт только имена образов из серверного Compose; данные, секреты, volumes и сети сервера не используются. Тестовые services не публикуют портов. Для контейнерного генератора требуется минимум шесть CPU Docker: все сервисы приложения совместно используют cpuset 0–3, генератор — 4–5. Лимиты памяти сервисов приложения суммарно меньше 8 ГБ; worker дополнительно ограничен двумя CPU. На отдельном сервере четыре CPU доступны всему приложению, а генератор запускается на другой машине. По завершении удаляются только тома и сети отдельного тестового проекта. Результаты остаются в игнорируемом .artifacts/.

Прогон создаёт 1 000 вузов, 10 000 проектов, 200 000 событий, 50 пользователей, выполняет интерактивные запросы одновременно с десятью выгрузками и импортом 20 000 строк, сохраняет p95, фоновые времена, файлы, OpenAPI и EXPLAIN ANALYZE. Сбой критерия p95 ≤1с либо ошибка API завершает команду ошибкой. Время генерации/очереди не считается интерактивной задержкой. Дополнительный прогон останавливает Redis/S3/Keycloak и принудительно завершает worker во время задания; после восстановления проверяются результат, повторные попытки и защищённое скачивание. Контейнер Linux внутри Docker Desktop не заменяет отдельную приёмку на согласованном сервере 4 vCPU / 8 ГБ.

Клиентские экраны, навигация без перезагрузки и мобильные сценарии описаны в [руководстве клиента](./frontend/guide.md), устройство и воспроизводимые проверки — в [техническом описании](./frontend/architecture.md). Организационная приёмка защиты данных выполняется заказчиком.

Архитектурная модель: [crm-stage2.archimate](architecture/crm-stage2.archimate). Проверена загрузкой, сохранением и генерацией трёх представлений в Archi 5.10.0.

## Ограничения ресурсов и сервисный доступ

API/worker используют client_credentials клиента crm-directory, которому bootstrap назначает только realm-management view-users/query-users/view-realm и соответствующие scope mappings. view-realm необходим для чтения участников ролей в Keycloak 26.4; права manage-* отсутствуют. Пароль администратора не передаётся runtime. Запросы каталога имеют таймаут и постраничный обход; секрет задаётся в `.env` и может ротироваться повторным keycloak-config.

`MAX_ACTIVE_UPLOADS`/`MAX_ACTIVE_UPLOADS_PER_USER` ограничивают буферные загрузки до Multer в каждой реплике API (4/2). PostgreSQL атомарно ограничивает задания: активные выгрузки на сотрудника/глобально — 10/200, сохранённые выгрузки на сотрудника — 100; активные импорты — 2, сохранённые — 10. Значения меняются через `.env`; PREVIEW импорта занимает активное место до apply или истечения. Ответ 429 означает превышение бюджета. Реплики API не разделяют счётчик загрузок; при масштабировании согласуйте общий лимит reverse proxy.

Все записи результата и ошибок импорта проверяют executionId и действующую lease. Потерявший аренду worker прекращает новые строки и не может продлить истёкшую аренду или завершить чужое задание. Health worker учитывает crm-sync вместе с очередями импорта/выгрузок. Backup/restore выполняются с UID/GID запускающего пользователя, чтобы закрытые каталоги с правами 0700 оставались доступны после перехода runtime на непривилегированного пользователя.

## Окружение и документация API

`NODE_ENV=production` отключает регистрацию Swagger UI, JSON/YAML и ресурсов интерфейса. Значение уже задано production-образом API. Серверный Compose не должен переопределять его локальным `development`. Для staging и тестов готовый образ можно запускать с явным `NODE_ENV=staging` или `test`; в этих окружениях документация открывается без входа. См. [OpenAPI](./openapi.md).

## Служебные HTTP-адреса worker

Worker не является приложением NestJS HTTP и не входит в публичную спецификацию CRM. Служебный сервер слушает `WORKER_HEALTH_PORT` (по умолчанию 3001) во внутренней Docker-сети:

- `GET /health` — проверки Redis/обоих worker и PostgreSQL: 200 с `{ "status": "ok" }` либо 503 с `{ "status": "unavailable" }`. При исключении возможен пустой ответ 503. Текущая реализация возвращает эту проверку и для других адресов, кроме `/metrics`.
- `GET /metrics` — текстовый формат Prometheus, без токена. Адрес предназначен для внутреннего сборщика метрик.

Не публикуйте служебный порт через внешний nginx. Эти адреса доступны и в production для наблюдаемости; они не являются Swagger.
